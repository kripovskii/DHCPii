# DHCP-сервер на Go

Небольшой (на данный момент) DHCPv4-сервер на Go. Проект намеренно начинается с простой реализации в памяти и

не пытается сразу стать production-системой.

## Цель

Реализовать минимальный обмен DHCP:

```text

DHCPDISCOVER  ->  DHCPOFFER

DHCPREQUEST   ->  DHCPACK

```

Сервер должен уметь выбрать свободный IPv4-адрес из пула, запомнить его за

клиентом и вернуть базовые сетевые параметры.

## Что изучаем

- структуру DHCPv4-пакета;

- DHCP options и формат TLV;

- UDP в Go;

- сериализацию и парсинг бинарных данных;

- простую state machine;

- синхронизацию доступа к общему состоянию;

- unit-тестирование сетевого кода.

## Упрощённая архитектура

```text

UDP
 |
 v
dhcp.Parse
 |
 v
server.Handle
 |
 +--> lease.Pool
 |
 v
dhcp.Encode
 |
 v
UDP

```

Планируемая структура:

```text

.
├── README.md
├── main.go
├── dhcp/
│   ├── message.go
│   ├── options.go
│   ├── parser.go
│   └── encoder.go
├── server/
│   └── server.go
└── lease/
    └── pool.go

```

## Первая версия

В первой версии планируется:

- DHCPv4;

- `DHCPDISCOVER`;

- `DHCPOFFER`;

- `DHCPREQUEST`;

- `DHCPACK`;

- пул адресов в памяти;

- идентификацию клиента по Client Identifier или MAC-адресу;

- subnet mask, router, DNS и lease time.

Пока не поддерживаем(временно):

- DHCPv6;

- DHCP relay и option 82;

- SQLite и восстановление после перезапуска;

- отказоустойчивость;

- несколько подсетей;

- PXE;

- сложные правила выдачи адресов.

## Пример конфигурации для первой версии

Пока конфигурацию можно задать непосредственно в `main.go`:

```go

config := Config{

    ServerIP:  net.ParseIP("192.168.1.1"),

    Router:    net.ParseIP("192.168.1.1"),

    DNS:       []net.IP{net.ParseIP("8.8.8.8")},

    LeaseTime: time.Hour,

}

```

Пул адресов:

```go

pool := lease.NewPool(

    net.ParseIP("192.168.1.100"),

    net.ParseIP("192.168.1.110"),

)

```

>[!CAUTION]
>DHCP использует UDP-порт 67 и broadcast-пакеты. Не запускай сервер в рабочей сети без изоляции: он может начать отвечать настоящим клиентам и нарушить работу существующего DHCP-сервера. Для экспериментов лучше использовать отдельную виртуальную сеть, Docker network или Linux network namespace.
